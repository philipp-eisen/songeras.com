## Priority 2: Extract Repeated Convex Helpers (Removes Boilerplate)

These patterns are repeated verbatim and force readers to mentally skip boilerplate to understand the business logic.

### 2.1 Extract `verifyGameAccess` helper in timelines.ts

**Problem:** Same 15-line auth check repeated 4 times in queries
**Impact:** Each query becomes clearer - readers see business logic, not auth boilerplate

```typescript
// Before: 15 lines of auth/access checking in each query
const identity = await ctx.auth.getUserIdentity()
if (!identity) return null
const game = await ctx.db.get("games", args.gameId)
if (!game) return null
const isHost = game.hostUserId === identity.subject
if (!isHost) {
  const playerSeat = await ctx.db.query('gamePlayers')...
  if (!playerSeat) return null
}

// After: 1 line
const access = await verifyGameAccess(ctx, args.gameId)
if (!access) return null
```

**Files:** `/convex/timelines.ts`

- Add helper function at top (~15 lines)
- Simplify 4 queries: `getPlayerTimeline`, `getAllTimelines`, `getCurrentRoundSongPreview`, `getCurrentRoundCard`
- **Net: ~45 lines saved, queries much easier to read**

### 2.2 Extract `reindexPlayerSeats` helper in games.ts

**Problem:** Identical 12-line pattern in `removeLocalPlayer` and `leave`
**Impact:** DRY violation removed, intent becomes clearer

```typescript
// Before: 12 lines repeated twice
const remainingPlayers = await ctx.db.query('gamePlayers')...
remainingPlayers.sort((a, b) => a.seatIndex - b.seatIndex)
for (let i = 0; i < remainingPlayers.length; i++) {
  if (remainingPlayers[i].seatIndex !== i) {
    await ctx.db.patch("gamePlayers", remainingPlayers[i]._id, { seatIndex: i })
  }
}

// After: 1 line
await reindexPlayerSeats(ctx, gameId)
```

**Files:** `/convex/games.ts`

- Add helper function (~12 lines)
- Replace in `removeLocalPlayer` (lines 252-268)
- Replace in `leave` (lines 390-404)
- **Net: ~12 lines saved, clearer intent**

### 2.3 Extract `fetchTimelineCards` helper in timelines.ts

**Problem:** Same card+track fetching loop appears in `getPlayerTimeline` and `getAllTimelines`
**Impact:** Reduces code duplication, makes the data flow clearer

**Files:** `/convex/timelines.ts`

## Priority 3: Simplify Complex Frontend Code

### 3.1 Use `arrayMove` from @dnd-kit/sortable

**Problem:** Manual array splice implementation (4 lines) when library utility exists
**Impact:** Uses well-tested utility, signals intent better

```typescript
// Before
const result = [...currentItems]
const [removed] = result.splice(oldIndex, 1)
result.splice(overIndex, 0, removed)
newItems = result

// After
import { arrayMove } from '@dnd-kit/sortable'
newItems = arrayMove(currentItems, oldIndex, overIndex)
```

**Files:** `/src/components/play/game-controls-bar.tsx` (lines 286-290)

### 3.2 Consolidate DnD sync effects (Consider carefully)

**Problem:** Two coordinated useEffects with long explanatory comments (lines 121-169)
**Trade-off:** The comments explain subtle coordination - removing them might hurt understanding

**Recommendation:** Keep as-is for now. The comments document important behavior. Refactoring to the store would move complexity, not eliminate it.

- **`ErrorMessage` component** - The pattern `{error && <p className="text-sm text-destructive">{error}</p>}` is simple and readable inline

- **`useMutationState` hook** - The try/catch pattern in lobby-view.tsx is straightforward; a hook would add indirection
