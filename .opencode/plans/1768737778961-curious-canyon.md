# Codebase Complexity Analysis

An audit of areas in the Songeras codebase that are overly complex, with recommendations for simplification.

## High Priority Issues

### 1. N+1 Query Patterns in Backend

**Locations:**

- `convex/timelines.ts:190-224` - `getAllTimelines` fetches cards/tracks in nested loops
- `convex/timelines.ts:86-101` - `getPlayerTimeline` same pattern
- `convex/turns.ts:53-73` - `getPlayerTimeline` helper
- `convex/games.ts:869-931` - `listMine` fetches games individually

**Problem:** For each player/entry, code fetches cards and tracks one at a time creating O(n\*m) database reads.

```typescript
// Current - O(n*m) reads
for (const entry of entries) {
  const card = await ctx.db.get('gameCards', entry.cardId) // N+1
  const track = await ctx.db.get('playlistTracks', card.trackId) // N+1
}
```

**Simplification:** Batch fetch all cards/tracks upfront:

```typescript
// Improved - O(1) reads
const cardIds = entries.map((e) => e.cardId)
const cards = await Promise.all(
  cardIds.map((id) => ctx.db.get('gameCards', id)),
)
const trackIds = cards.map((c) => c.trackId)
const tracks = await Promise.all(
  trackIds.map((id) => ctx.db.get('playlistTracks', id)),
)
```

### 2. Missing Index + Using .filter()

**Location:** `convex/schema.ts:159-170` and `convex/games.ts:869-874`

**Problem:** No `by_userId` index on `gamePlayers` table forces inefficient `.filter()`:

```typescript
const playerSeats = await ctx.db
  .query('gamePlayers')
  .withIndex('by_gameId_and_userId') // Can't efficiently find all games for user
  .filter((q) => q.eq(q.field('userId'), identity.subject)) // Scans all rows!
```

**Simplification:** Add index to schema.ts:

```typescript
.index('by_userId', ['userId'])
```

Then query directly:

```typescript
const playerSeats = await ctx.db
  .query('gamePlayers')
  .withIndex('by_userId', (q) => q.eq('userId', identity.subject))
  .collect()
```

**Locations:**

- `convex/games.ts:78-83,168-172,218-222` etc. (15+ occurrences)

## Lower Priority Issues

### 11. Inconsistent Error Handling Patterns

**Problem:** Mix of:

- Components use `wrapAction` (BetControls, ActionButtons)
- Components use local `useState` (LobbyView, ImportPlaylistCard)
- Actions return null on error vs throw vs Result type

**Simplification:** Standardize patterns:

- Game mutations: Use `wrapAction` from store
- Non-game mutations: Create similar `useMutationState` hook
- Backend: Use Result type pattern for actions

### 12. Duplicated Seat Re-indexing Logic

**Location:** `convex/games.ts:253-268` and `391-404`

**Simplification:** Extract helper:

```typescript
async function reindexPlayerSeats(ctx, gameId) {
  const players = await ctx.db
    .query('gamePlayers')
    .withIndex('by_gameId', (q) => q.eq('gameId', gameId))
    .collect()
  players.sort((a, b) => a.seatIndex - b.seatIndex)
  for (let i = 0; i < players.length; i++) {
    if (players[i].seatIndex !== i) {
      await ctx.db.patch('gamePlayers', players[i]._id, { seatIndex: i })
    }
  }
}
```

### 13. Repeated Game State Validation in Mutations

**Location:** `convex/turns.ts` - Same pattern in 7 mutations

**Simplification:** Create helper:

```typescript
async function getActiveGame(ctx, gameId: Id<'games'>, validPhases: string[]) {
  const game = await ctx.db.get('games', gameId)
  if (!game) throw new Error('Game not found')
  if (!validPhases.includes(game.phase)) throw new Error('Invalid phase')
  if (!game.currentRound) throw new Error('No active round')
  return game
}
```

## Recommended Implementation Order

1. **Add `by_userId` index** - Quick schema change, immediate performance win
2. **Fix N+1 queries** - Batch fetches in timeline and game queries
3. **Create auth helpers** - `requireAuth`, `verifyGameAccess`
4. **Create shared validators** - `convex/validators.ts`
5. **Extract DnD sync hook** - `useDndTimelineSync`
6. **Break up resolveRound** - Extract helper functions
7. **Extract CreateGameSection** - Move to separate component file
8. **Config-driven ActionButtons** - Reduce repetitive rendering
