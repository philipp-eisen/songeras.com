# Plan: Switch Deployment to Cloudflare Workers

## Overview

Migrate from manual Nitro/Node.js deployment to Cloudflare Workers with:

- **Production**: Deploy to `cf.songeras.com` on `main` branch pushes
- **Preview**: Deploy to `*.preview.songeras.com` on PR branches
- **Convex Preview Deployments**: Separate Convex backend per preview branch

## Prerequisites (User Actions Required)

Before implementation, you need to:

### 1. Cloudflare Setup

- [ ] Get your **Cloudflare Account ID** from the dashboard URL or overview page
- [ ] Create a **Cloudflare API Token** with `Workers Scripts:Edit` and `Account:Read` permissions
  - Go to: https://dash.cloudflare.com/profile/api-tokens
  - Use template "Edit Cloudflare Workers"

### 2. Convex Setup (Two Separate Keys Required)

Go to: https://dashboard.convex.dev → Project Settings → Deploy Keys

- [ ] Generate a **Production Deploy Key** (click "Generate Production Deploy Key")
- [ ] Generate a **Preview Deploy Key** (click "Generate Preview Deploy Key")

These are separate keys with different permissions:

- Production key can only deploy to your production backend
- Preview key can create/deploy to preview backends (isolated per branch)

### 3. GitHub Secrets

Add these secrets to your repo (Settings → Secrets and variables → Actions):

- [ ] `CLOUDFLARE_API_TOKEN` - Your Cloudflare API token
- [ ] `CLOUDFLARE_ACCOUNT_ID` - Your Cloudflare account ID
- [ ] `CONVEX_DEPLOY_KEY` - Your **Production** Convex deploy key
- [ ] `CONVEX_DEPLOY_KEY_PREVIEW` - Your **Preview** Convex deploy key

### 4. DNS Configuration (Cloudflare Dashboard)

- [ ] Add CNAME record: `cf.songeras.com` → `songeras.workers.dev`
- [ ] Add wildcard CNAME: `*.preview.songeras.com` → `songeras.workers.dev`
  - Note: Wildcard DNS requires Cloudflare Pro plan or using their proxy

## Implementation Steps

### Step 1: Install Cloudflare dependencies

```bash
pnpm add -D @cloudflare/vite-plugin wrangler
```

### Step 2: Update `vite.config.ts`

Replace the `nitro` plugin with `cloudflare`:

```typescript
import { defineConfig } from 'vite'
import { devtools } from '@tanstack/devtools-vite'
import { tanstackStart } from '@tanstack/react-start/plugin/vite'
import viteReact from '@vitejs/plugin-react'
import viteTsConfigPaths from 'vite-tsconfig-paths'
import tailwindcss from '@tailwindcss/vite'
import { cloudflare } from '@cloudflare/vite-plugin'

const config = defineConfig({
  plugins: [
    devtools(),
    cloudflare({ viteEnvironment: { name: 'ssr' } }),
    viteTsConfigPaths({
      projects: ['./tsconfig.json'],
    }),
    tailwindcss(),
    tanstackStart(),
    viteReact(),
  ],
  ssr: {
    noExternal: ['@convex-dev/better-auth'],
  },
})

export default config
```

### Step 3: Create `wrangler.jsonc`

```jsonc
{
  "$schema": "node_modules/wrangler/config-schema.json",
  "name": "songeras",
  "compatibility_date": "2025-01-14",
  "compatibility_flags": ["nodejs_compat"],
  "main": "@tanstack/react-start/server-entry",
  "routes": [
    { "pattern": "cf.songeras.com", "custom_domain": true },
    { "pattern": "*.preview.songeras.com", "custom_domain": true },
  ],
}
```

### Step 4: Update `package.json` scripts

```json
{
  "scripts": {
    "dev": "npx convex dev --once && concurrently -r npm:dev:web npm:dev:db",
    "dev:web": "vite dev",
    "dev:db": "convex dev",
    "build": "vite build && tsc --noEmit",
    "preview": "vite preview",
    "deploy": "pnpm run build && wrangler deploy",
    "deploy:preview": "pnpm run build && wrangler deploy --env preview",
    "test": "vitest run",
    "lint": "eslint",
    "format": "prettier",
    "check": "prettier --write . && eslint --fix",
    "cf-typegen": "wrangler types"
  }
}
```

### Step 5: Create GitHub Actions Workflow

Create `.github/workflows/deploy.yml`:

```yaml
name: Deploy

on:
  push:
    branches: [main]
  pull_request:
    types: [opened, synchronize, reopened]

jobs:
  deploy-production:
    if: github.ref == 'refs/heads/main' && github.event_name == 'push'
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: pnpm/action-setup@v4
        with:
          version: 9

      - uses: actions/setup-node@v4
        with:
          node-version: '22'
          cache: 'pnpm'

      - run: pnpm install --frozen-lockfile

      # Deploy Convex production (uses Production Deploy Key)
      # The deploy command sets VITE_CONVEX_URL automatically
      - name: Deploy Convex & Build
        run: npx convex deploy --cmd 'pnpm run build'
        env:
          CONVEX_DEPLOY_KEY: ${{ secrets.CONVEX_DEPLOY_KEY }}

      - name: Deploy to Cloudflare
        uses: cloudflare/wrangler-action@v3
        with:
          apiToken: ${{ secrets.CLOUDFLARE_API_TOKEN }}
          accountId: ${{ secrets.CLOUDFLARE_ACCOUNT_ID }}

  deploy-preview:
    if: github.event_name == 'pull_request'
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: pnpm/action-setup@v4
        with:
          version: 9

      - uses: actions/setup-node@v4
        with:
          node-version: '22'
          cache: 'pnpm'

      - run: pnpm install --frozen-lockfile

      # Deploy Convex preview (uses Preview Deploy Key)
      # When using Preview key, convex deploy automatically:
      # 1. Creates/updates a preview deployment named after the git branch
      # 2. Sets VITE_CONVEX_URL to the preview backend URL
      # 3. Runs the build command with correct env vars
      - name: Deploy Convex Preview & Build
        run: npx convex deploy --cmd 'pnpm run build' --preview-create "${{ github.head_ref }}"
        env:
          CONVEX_DEPLOY_KEY: ${{ secrets.CONVEX_DEPLOY_KEY_PREVIEW }}

      # Deploy preview to Cloudflare with branch-specific name
      - name: Deploy Preview to Cloudflare
        id: cloudflare-deploy
        uses: cloudflare/wrangler-action@v3
        with:
          apiToken: ${{ secrets.CLOUDFLARE_API_TOKEN }}
          accountId: ${{ secrets.CLOUDFLARE_ACCOUNT_ID }}
          command: deploy --name songeras-pr-${{ github.event.pull_request.number }}

      - name: Comment PR with preview URL
        uses: actions/github-script@v7
        with:
          script: |
            github.rest.issues.createComment({
              issue_number: context.issue.number,
              owner: context.repo.owner,
              repo: context.repo.repo,
              body: `## Preview Deployment Ready
              
              **Frontend:** https://songeras-pr-${{ github.event.pull_request.number }}.workers.dev
              
              The Convex preview backend is automatically created for branch \`${{ github.head_ref }}\`.
              View it in the [Convex Dashboard](https://dashboard.convex.dev).
              
              Preview will be automatically updated on new commits.`
            })
```

**Key differences from Vercel setup:**

- We use `CONVEX_DEPLOY_KEY` (Production key) for `main` branch
- We use `CONVEX_DEPLOY_KEY_PREVIEW` (Preview key) for PRs
- The `--preview-create` flag explicitly names the preview deployment after the branch
- Convex's `deploy` command automatically sets `VITE_CONVEX_URL` before running the build

### Step 6: (Optional) Set Default Convex Environment Variables

If your Convex functions need environment variables (like `SITE_URL`, API keys), set default values for preview deployments in the Convex Dashboard:

1. Go to Convex Dashboard → Project Settings
2. Scroll to "Default Environment Variables"
3. Add variables that preview deployments should inherit

This ensures preview backends have the necessary config without manual setup per branch.

### Step 7: Remove unused dependencies

```bash
pnpm remove nitro
```

### Step 8: Update `.gitignore`

Add Cloudflare artifacts:

```
.wrangler
.dev.vars
```

## Notes

### Cloudflare Preview URLs

- Preview deployments use `songeras-pr-{number}.workers.dev` URLs by default
- Custom subdomain routing (`*.preview.songeras.com`) requires Cloudflare Workers Routes configuration (can be added later)

### Convex Preview Deployments

- **Isolated backends**: Each preview has its own database, functions, and config (no shared data with production)
- **Auto-cleanup**: Preview deployments are deleted after 5 days (14 days on Pro plan) or when a new deployment with the same branch name is created
- **Fresh data**: Preview backends start empty - use `--preview-run 'seedFunction'` if you need initial data
- **Dashboard visibility**: Preview deployments appear in the deployment picker in Convex Dashboard

### Two Deploy Keys Explained

- **Production Deploy Key**: Can only deploy to your production backend. Used on `main` branch.
- **Preview Deploy Key**: Can create and deploy to preview backends. Used on PR branches.
- This separation ensures PR deployments can't accidentally affect production.
